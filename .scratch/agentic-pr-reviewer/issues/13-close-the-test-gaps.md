# 13 — Close the test gaps

**What to build:** Unit coverage for the parts of the system that decide whether a review runs at all, plus a structural guard against symbols silently disappearing from a package's public surface. Every module in the review pipeline is tested except the composition root of the action itself: the module that maps GitHub's `INPUT_*` environment convention onto action inputs, reads the event-path variable and parses the event payload, builds the clients, and guards the whole entrypoint behind the `GITHUB_ACTIONS` environment check has no test file at all, so a regression there fails every consumer's workflow with no unit signal whatsoever. Cover it end to end: the input-name mapping — uppercasing and space-to-underscore, with dashes preserved — a missing required input, an absent event-path variable, an unreadable event file, a malformed event file, and the entrypoint guard together with the top-level catch that logs `review.failed` and sets a non-zero exit code. This will likely require extracting a small testable seam out of `main()` so the module can be imported and exercised without executing the action as a side effect of the import. Then close the remaining untested leaves — the Anthropic client factory and the token-usage accumulator in `packages/ai`, and the pull-request event schema in `packages/schemas` — and add a barrel-export guard per package: a test that asserts each package's public entry point still exports its documented symbol set, so a symbol dropped from a barrel during a refactor fails the suite instead of vanishing silently, which is exactly the failure mode ticket 11's deletions could introduce. Everything here stays in the fast unit run: no real model calls, no network.
