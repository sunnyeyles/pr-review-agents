# 16 — Ship v1

**What to build:** The first real release. The reviewer is feature-complete, but it has never reviewed a pull request in anger and no version tag exists, so nothing about the running system is proven outside tests. Four things turn it live. First, verify that the default model id declared on the action's `model` input is a model that currently serves traffic — it is the single hardcoded model identifier in the codebase, inherited by every consumer who does not override it, and a stale alias would fail on their very first run with an error that reads as though the action itself is broken. Second, configure the credentials the running system needs: the Anthropic key the self-review workflow authenticates the agents with, and, for the release workflow, the repository variable naming the public destination repository plus the token that pushes to it. These belong in repository or organisation secrets and variables — they must never be inlined into source, into a workflow file, or into the published bundle, and the verification steps below must confirm their presence without ever printing their values. Third, confirm the self-review workflow performs an actual review end to end rather than skipping: it is written to no-op when the key is absent, and its runs currently finish in seconds, which is the signature of a skip, not of a review. A genuine run reviews a pull request and publishes the check run — or, on a fork pull request where the token cannot write checks, falls back to the job summary. Fourth, cut the first version tag and confirm the release workflow lands the action metadata, the built bundle, the README, and the LICENSE in the public action repository, with the floating major-version alias moved to point at the new tag. Closing note: this ticket needs credentials only the repository owner can set, so the verification steps are agent-runnable but a human is required in the loop for the secrets and for the tag.

**Blocked by:** 13 — Close the test gaps (the release should carry proven plumbing); 14 — Make the release pipeline trustworthy (the release path itself must be proven before the first tag); 15 — Agent evaluation fixtures (review quality should be measured, not assumed).
