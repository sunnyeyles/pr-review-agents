# 11 — Remove the AWS-era residue

**What to build:** A single cleanup pass that finishes the pivot from the AWS Lambda/SQS delivery path to the GitHub Action, so that nothing dead ships in the bundle and no doc describes a system that no longer exists. The dead code goes: the GitHub App auth factory `createGithubApp`, `defaultCreateOctokit`, the `GithubAppConfig` and `InstallationClientFactory` types, and the now-unused `@octokit/auth-app` dependency; the SQS `reviewJobSchema` and its `ReviewJob` type together with their test file; the unused `AgentOutput` and `SUPPORTED_PULL_REQUEST_ACTIONS` barrel exports; and the leftover Terraform entries in `.gitignore`. Critically, `createInstallationClient` is NOT dead and must be kept — `packages/github/src/token.ts` calls it, and it is the shared client body sitting behind the live token auth path. The delicate part is `packages/github/src/app.test.ts`, which imports only the dead `createGithubApp` factory and therefore exercises live client code through a dead entry point; those 23 tests must be re-pointed at `createTokenClient` with the octokit factory injected, so every existing behaviour survives — PR mapping, pagination, the diff media type, file-content error handling, search scoping, and check-run creation — which also closes the standing gap that the only auth path production actually uses has no tests of its own. The deletions force a docs realignment: strip the stale Lambda, SQS, and Secrets Manager references from doc comments (roughly sixteen references across nine files, including the reviewer's shared end-to-end entry point, the action entrypoint, and the synthesiser), correct the README observability section which lists `agent.thinking` and `agent.message` events that nothing emits while omitting the `review.skipped` and `review.published.degraded` events that are emitted, delete the "Two graphs, two altitudes" section which became false when the agent StateGraph was replaced by a plain loop, fix the agent runtime comment that describes a "plain while" loop over what is actually a `for` loop, and drop the exact "241 tests across 17 files" figure outright rather than updating it, since a number that goes stale on every added test is a liability.
